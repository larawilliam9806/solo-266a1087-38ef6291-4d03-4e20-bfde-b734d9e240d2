# 水质实验室 · 批次修订发布台

供水质实验室数据员使用的批次修订发布页（Flask + SQLite）。浏览器上传仪器导出的
CSV、填写批次号，系统逐行校验后预览**新增 / 修改 / 撤回（删除）**差异，确认后
**整批替换**下游采集程序读取的本地 CSV，并在网页登记当前版本与行数。

同时提供**浏览器盲化供数页**：为多家合作方分别建立独立盲化域，选择任一已发布
版本，下载仅含 **盲码 / 检测项目 / 浓度** 三列的 CSV；同一合作方的样本盲码跨
版本稳定（可追踪修订），不同合作方盲码不同（无法互相串联），盲码不可从样本号
或连续编号推算，主密钥重启后保持。支持 docker compose 一键启动。

## 功能与规则

- 上传 CSV 必须包含三列（表头兼容中英文）：`样本号`、`检测项目`、`浓度(mg/L)`
  （亦接受 `sample_no / analyte / concentration` 等常见别名，UTF-8、支持 BOM）。
- 逐行业务校验，错误带行号提示：
  - 同一样本同一检测项目不得重复；
  - 浓度必须是数字且 **≥ 0**（拒绝负数、空值、NaN、Inf、非数字）；
  - 样本号、检测项目不能为空，列数必须与表头一致。
- 上传内容代表修订后的**完整一批**：当前版本中存在、但本次 CSV 未包含的行，
  在预览中列为「撤回（删除）」，确认后该检测结果即被撤回。
- 预览页分类展示新增、修改（旧值→新值）、撤回、不变四类差异，确认后才发布。
- 首页登记当前版本号、批次号、行数、发布时间（UTC）与内容 SHA256，并提供
  已发布 CSV 的在线查看入口和事件日志（含每次恢复记录）。

## 本地启动

环境要求：Python 3.10+（仅依赖 Flask）。

```bash
cd wq-publish
./run.sh                 # 自动创建 .venv、安装 flask，监听 http://127.0.0.1:5000
```

手动方式：

```bash
python3 -m venv --without-pip .venv   # 若系统带 ensurepip，直接 python3 -m venv .venv
# 按你的环境引导 pip 后：
.venv/bin/pip install -r requirements.txt
WQ_DATA_DIR=$PWD/data WQ_DOWNSTREAM_DIR=$PWD/downstream \
  .venv/bin/flask --app wsgi:create_app run --host 127.0.0.1 --port 5000
```

环境变量（可选）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WQ_DATA_DIR` | `./data` | SQLite 数据库、flask 密钥、盲化主密钥、盲化导出、隔离区存放目录 |
| `WQ_DOWNSTREAM_DIR` | `./downstream` | 下游采集程序读取目录，正式文件固定名为 `published_results.csv` |
| `WQ_HOST` / `WQ_PORT` | `0.0.0.0` / `5000` | 仅容器入口（waitress）使用 |

下游采集程序只需固定读取 `WQ_DOWNSTREAM_DIR/published_results.csv`。

## Docker Compose 启动

```bash
cd wq-publish
docker compose up -d --build      # 监听 127.0.0.1:5000（仅本机，对外请前置反代）
docker compose logs -f wq-publish
```

两个命名卷承载全部持久化状态，容器重建/升级后数据与盲码保持不变：

| 卷 | 容器内路径 | 内容 |
| --- | --- | --- |
| `wq-data` | `/data` | SQLite、`blind_master_key`（盲化主密钥，0600）、盲化导出、隔离区 |
| `wq-downstream` | `/downstream` | 正式供数 `published_results.csv` |

容器以非 root（uid 10001）、单实例 waitress 运行；并发正确性依赖同一 SQLite
文件锁与同目录原子改名，**不要**把副本扩成多实例。

## 合作方盲化供数

入口为顶部导航「合作方盲化供数」（`/partners`）。

**操作流程**

1. 「建立合作方」：填写名称（不可重名），系统为该合作方建立独立盲化域。
2. 进入合作方详情页，在下拉框选择一个**已发布版本**，点击「生成并获取下载地址」。
3. 每条导出生成不可猜测的固定地址 `/blind/<token>`，合作方通过该地址下载 CSV，
   内容只有三列：`盲码,检测项目,浓度(mg/L)`，不含样本号或任何可关联标识，
   行按盲码排序，不携带原始样本顺序。
4. 终止合作时点击「撤销合作方」：撤销立即生效。

**盲码如何满足各项要求**

- 盲码 = `base32hex(HMAC-SHA256(主密钥, 域标识‖合作方id‖样本号))` 前 10 字节
  （80 bit，定长 16 字符），是带密钥的伪随机函数输出：
  - **跨版本稳定**：同样本号在同合作方的任意版本导出中盲码一致，合作方可追踪修订；
  - **跨合作方不同**：合作方 id 作为 HMAC 域分隔输入，两机构对同样本的盲码
    互不相关，拿到彼此文件也无法串联；
  - **不可推算**：没有主密钥就无法验证/枚举盲码，连续样本号（S001、S002…）
    的输出相互独立，既不能反推样本号也不能按顺序枚举；
  - **重启保持**：主密钥是首次启动时生成的 32 字节随机数，持久化在
    `WQ_DATA_DIR/blind_master_key`（权限 0600、原子改名写入），重启/重建容器不变。
- 80 bit 空间内碰撞概率可忽略；代码仍对每次导出做显式碰撞校验，碰撞即拒绝生成。

**撤销、并发与失败的语义保证**

- **撤销后旧地址不再取数**：下载处理只在「导出 ready 且合作方未撤销」时放行，
  撤销后该合作方的全部地址返回 410，且不再受理新导出请求。
- **已受理的下载可完整结束**：撤销只翻转数据库状态、不删除任何就绪文件；
  响应开始时已打开独立文件句柄，下载全程可读完，不受撤销影响。
- **导出只含一个完整版本**：导出只能基于 `results` 表中已发布的完整版本，
  全量渲染该版本数据；与新发布/撤销交错时，写事务（`BEGIN IMMEDIATE`）保证
  每条导出绑定单一版本，撤销生效后新请求一律被拒。
- **失败不留可用的部分导出**：导出登记先以 `building` 落库，文件经
  「同目录临时文件 + fsync + 原子改名」生成，成功才置 `ready`；任何失败都会
  把登记置 `failed` 并删除半成品，地址返回 410。盲化文件全部位于
  `WQ_DATA_DIR/blind_exports/`，与下游正式供数目录完全隔离，
  **原始供数 `published_results.csv` 不受任何盲化操作影响**。
- **崩溃恢复**：启动时自动清理半写临时文件；未完成的 `building` 导出置
  `failed` 并清掉半成品；`ready` 导出文件缺失/哈希不符时，因盲码可确定性
  复现，按数据库登记重建；盲化目录中的游离文件移入 quarantine。全部动作写入
  事件日志。

## 操作流程

1. 打开首页，填写批次号并选择仪器导出的 CSV，点击「校验并预览增删改」。
2. 校验失败：回到首页逐条显示带行号的错误，修正后重新上传，不产生任何数据变更。
3. 校验通过：进入预览页核对新增/修改/撤回差异，可「放弃本次修订」或
   「确认无误，整批替换并发布」。
4. 发布成功后回到首页，登记版本号递增、行数更新，下游文件已原子替换。

## 数据一致性设计（如何保证要求）

**下游只会读到完整旧版或新版**

- 发布时先把新 CSV 写入下游目录内的同目录临时文件（`.tmp-publish-*.csv`），
  `flush + fsync` 后调用 `os.replace` 原子改名覆盖正式文件，并 fsync 目录。
  改名瞬间下游要么看到旧文件、要么看到完整新文件，不会读到半写内容；
  临时文件以 `.` 开头且与正式文件名不同，不会被按固定文件名读取的采集程序读到。

**文件与登记的事务关系、崩溃自动恢复**

- SQLite（`data/wq_publish.db`）是版本登记与全版本结果的唯一真相源，
  发布在 `BEGIN IMMEDIATE` 事务内完成「原子换文件 → 写新版本结果 → 更新登记表」。
- 每次启动（`Storage.recover()`）自动核对并修复：
  1. 清理崩溃遗留的 `.tmp-publish-*` 临时文件；
  2. 正式文件缺失或 SHA256 与登记不符时，以数据库登记为准原子重建；
  3. 「文件已改名但事务未提交」的现场，重启后回滚为登记中的完整版本；
  4. 下游目录中未登记的游离文件移入 `data/quarantine/` 隔离（不直接删除）；
  5. 超过 24 小时未确认的预览会话自动作废。
  所有恢复动作写入 `event_log` 并展示在首页。

**两个页面从同一版本发起修订，只允许一个成功**

- 每次预览生成带随机 token 的修订会话，记录发起时的基线版本 `base_version`。
- 确认发布时在写事务内重新比对当前版本：基线已被其他发布超越时，本会话
  标记为 `obsolete` 并返回 409 过期预览页（仍展示旧基线差异供核对），
  明确要求重新预览，绝不可能覆盖先发布者；重新预览后即可正常发布。
- 同一会话重复发布、已取消/已发布/已过期会话再次确认，一律拒绝。

## 自测

```bash
.venv/bin/python -I tests/selftest.py       # 原批次发布：42 项断言
.venv/bin/python -I tests/test_blinding.py  # 盲化供数：53 项断言
```

第一套覆盖：CSV 各类非法输入、上传→预览→发布全链路、增改删分类与撤回语义、
同版本双页面并发冲突（409 + obsolete + 重新预览成功）、文件缺失/损坏/临时文件/
游离文件/改名未提交五类崩溃恢复、会话取消与重复发布防护。

第二套覆盖：盲码的稳定性/域隔离/不可枚举/重启保持、导出仅三列且只含一个完整
版本、撤销后旧地址 410 与进行中下载完整结束、撤销/发布/新导出交错并发、
生成失败的 failed 原子性与原始供数不受影响、building/ready/游离文件三类崩溃恢复。

`examples/` 下提供 `batch_v1.csv`、`batch_v2_revision.csv`（含增改删）与
`batch_invalid.csv`（含重复、负数、空值）可直接在页面上演练。

## 部署提示与已知限制

- 本地 `flask run` 为开发服务器；容器与正式环境使用
  `waitress`（单实例多线程，见 `docker_entry.py`），也可用
  `waitress-serve --host 127.0.0.1 --port 5000 wsgi:create_app`。
  并发正确性依赖 SQLite 的 `BEGIN IMMEDIATE` 文件锁与同目录 `os.replace`，
  多 worker/多实例部署时必须共享同一个 `WQ_DATA_DIR` 与 `WQ_DOWNSTREAM_DIR`，
  且仅允许一个写入实例。
- 全量结果按版本保留在 `results` 表中，当前未提供历史版本回滚的页面入口
  （数据具备，可后续增加）；历史 CSV 文件本身只保留最新一版。
- 盲化导出文件按导出记录长期保留在 `data/blind_exports/`（撤销合作方也不删，
  供审计与进行中的下载使用），当前未提供定期清理入口。
- 上传上限 16MB；认证、权限控制未包含在本版本内，compose 默认仅绑定
  127.0.0.1，对外暴露建议前置反向代理加访问控制。
- 盲化主密钥一旦丢失，历史盲码将无法复现；请随 `wq-data` 卷一并备份，
  密钥泄露等于盲码可被反查。
